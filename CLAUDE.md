# CLAUDE.md

Учебный проект по курсу об архитектуре фронтенда: поиск сериалов через TVmaze API.
Главное здесь — архитектура, а не функциональность.

## Общение

- С пользователем общаемся на русском.
- Код, имена веток, коммиты и заголовки PR — на английском. Описание PR — на русском.

## Стек и команды

React 19, MobX, TypeScript, Vite, Biome.

- `npm run check` — Biome: линтер, форматирование, порядок импортов. Он же ловит лимит в 120 строк (правило 2.1).
- `npm run check:fix` — то же с автоисправлением.
- `npm run build` — проверка типов и сборка.

## Документы проекта

- [ARCHITECTURE.md](ARCHITECTURE.md) — обязательные правила, подключены ниже целиком.
- [conspects/](conspects/) — конспекты уроков, первоисточник правил. Целиком не загружаются: открывай, когда нужно понять, _почему_ правило именно такое.
- [README.md](README.md) — для людей и проверяющего. Правила там не пересказываем, а ссылаемся на `ARCHITECTURE.md`.

### Новый урок

1. Конспект кладём в `conspects/` с номером: `NN-short-topic.md` (`02-stores.md`).
2. Новые правила из него переносим в `ARCHITECTURE.md` в формате пронумерованных пунктов.
3. Если правило противоречит текущему коду или другому правилу — сначала обсуждаем с пользователем, потом меняем.

## Git-процесс

- **Никогда не коммить и не пушить напрямую в `main`.** Каждый push в `main` запускает деплой на GitHub Pages.
- Каждая задача делается в отдельной ветке от свежего `main`. Начало задачи — `/start-task`, завершение — `/finish-task`.
- Имена веток: `<тип>/<kebab-case-на-английском>`, коротко, 2–5 слов.
  - `feature/` — новая функциональность
  - `fix/` — исправление бага
  - `refactor/` — переработка без изменения поведения
  - `docs/` — документация, `ARCHITECTURE.md`, конспекты
  - `chore/` — настройки, зависимости, CI
- Сообщения коммитов: коротко, на английском, в нижнем регистре, как в истории проекта (`tune debounce and empty state`).
- В `main` ветка попадает только через Pull Request со squash merge. Merge делается только после явного подтверждения пользователя.
- Проверки делают git-хуки (`simple-git-hooks`, скрипты в `scripts/hooks/`): `pre-commit` запрещает коммит в `main` и гоняет Biome по файлам коммита, `pre-push` запрещает push в `main` и запускает `npm run build`. Не обходи их через `--no-verify`. После клонирования хуки ставятся сами при `npm install`.
