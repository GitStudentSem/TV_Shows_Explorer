## Архитектура

Правила архитектуры обязательны для любого изменения: [ARCHITECTURE.md](ARCHITECTURE.md).

## Git-процесс

- **Никогда не коммить и не пушить напрямую в `main`.** Каждый push в `main` запускает деплой на GitHub Pages.
- Каждая задача делается в отдельной ветке от свежего `main`. Начало задачи — `/start-task`, завершение — `/finish-task`.
- Имена веток: `<тип>/<kebab-case-на-английском>`, коротко, 2–5 слов.
  - `feature/` — новая функциональность
  - `fix/` — исправление бага
  - `refactor/` — переработка без изменения поведения
  - `docs/` — документация, `ARCHITECTURE.md`, конспекты
  - `chore/` — настройки, зависимости, CI
- Сообщения коммитов: коротко, на английском, в нижнем регистре, как в истории проекта (`tune debounce and empty state`).
- В `main` ветка попадает только через Pull Request со squash merge. Merge делается только после явного подтверждения пользователя.
- Перед открытием PR должны проходить `npm run check` и `npm run build`.
