# Завершить задачу

Дополнительный комментарий пользователя: $ARGUMENTS

## Шаги

1. **Проверь ветку:** `git branch --show-current`. Если это `main` — остановись: задачу нужно было начинать через `/start-task`. Предложи создать ветку сейчас (незакоммиченные изменения переедут в неё).
2. **Проверки сам не запускай** — их делают git-хуки (`scripts/hooks/`): `pre-commit` гоняет Biome по файлам коммита, `pre-push` — `npm run build`. Если коммит или push упал на хуке — остановись, покажи ошибку и предложи исправить. Не обходи хуки (`--no-verify`).
3. **Закоммить изменения**, если они есть:
   - посмотри `git status --short` и `git diff`;
   - не добавляй секреты, `.env`, временные и сгенерированные файлы; если сомневаешься в файле — спроси;
   - добавляй файлы явно по именам и сделай коммит с коротким сообщением на английском в нижнем регистре (стиль из `CLAUDE.md`).
4. **Проверь, что в ветке есть коммиты:** `git log --oneline main..HEAD`. Если пусто — остановись: нечего вливать.
5. **Запушь:** `git push -u origin HEAD`.
6. **Открой PR:** если PR для этой ветки уже есть (`gh pr view --json url,state`), используй его. Иначе `gh pr create --base main --title "<заголовок>" --body "<описание>"`:
   - заголовок — суть задачи коротко, на английском, в нижнем регистре; он станет сообщением squash-коммита в `main`;
   - описание на русском: что сделано и зачем (по `git log main..HEAD` и `git diff --stat main...HEAD`), плюс комментарий пользователя, если он есть.
7. **Остановись и спроси подтверждение.** Покажи ссылку на PR, заголовок и короткий список изменений. Спроси: «Вливаем в main? Это запустит деплой на GitHub Pages». Не делай merge без явного «да» от пользователя.
8. **После подтверждения:**
   - `gh pr merge --squash --delete-branch`;
   - убедись, что ты на `main` и он свежий: `git switch main` и `git pull --ff-only`;
   - покажи запуск деплоя: `gh run list --workflow deploy.yml --limit 1`.
9. **Отчитайся:** PR влит, ветка удалена, деплой запущен (ссылка на запуск).

Если пользователь хочет доработать задачу вместо merge — оставайся в ветке; следующий `/finish-task` обновит тот же PR.
