# Начать задачу

Описание задачи: $ARGUMENTS

Если описание пустое, спроси у пользователя, что за задача, и остановись.

## Шаги

1. **Проверь состояние:** `git status --short` и `git branch --show-current`.
   - Если ты на ветке, отличной от `main`, и в ней есть незакоммиченные изменения — остановись и спроси, что с ними делать (закоммитить в текущую ветку, отложить через `git stash` или перенести в новую задачу). Ничего не удаляй сам.
   - Если ты на `main` и есть незакоммиченные изменения — предупреди, что они переедут в новую ветку, и продолжай.
2. **Обнови main:** `git switch main` (если ещё не на нём) и `git pull --ff-only`. Если pull не проходит — остановись и покажи ошибку.
3. **Придумай имя ветки** по правилам из `CLAUDE.md`: тип (`feature/`, `fix/`, `refactor/`, `docs/`, `chore/`) + короткое имя на английском в kebab-case. Проверь, что такой ветки нет: `git branch -a --list "*<имя>*"`.
4. **Создай ветку:** `git switch -c <тип>/<имя>`.
5. **Отчитайся одной-двумя строками:** имя ветки и то, что можно начинать работу. Завершение задачи — `/finish-task`.

Не пушь ветку на этом шаге — это сделает `/finish-task`.
