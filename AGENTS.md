# AGENTS.md

Учебный проект по курсу об архитектуре фронтенда: поиск сериалов через TVmaze API.
Главное здесь — архитектура, а не функциональность.

Проект fullstack: клиент в `src/` (деплой на GitHub Pages), сервер в `server/` (Node + Express, деплой отдельно).
Клиент ходит только в наш сервер, сервер — в TVmaze. Что где живёт — раздел 9 в `ARCHITECTURE.md`.

## Общение

- С пользователем общаемся на русском.
- Код, имена веток, коммиты и заголовки PR — на английском. Описание PR — на русском.

## Стек и команды

Клиент: React 19, MobX, TypeScript, Vite. Сервер: Node 24, Express 5, TypeScript. Общий линтер — Biome.

- `npm install` — ставит зависимости клиента и через `postinstall` сервера (`server/` — отдельный пакет со своим `package.json`).
- `npm run dev` — клиент и сервер вместе. Vite проксирует `/api` на `localhost:3000`. По отдельности: `dev:client`, `dev:server`.
- `npm run check` — Biome по всему репозиторию: линтер, форматирование (в том числе `.md`), порядок импортов. Он же ловит лимит в 120 строк для кода (правило 2.1, на `.md` лимит не действует).
- `npm run check:fix` — то же с автоисправлением.
- `npm run build` — проверка типов и сборка клиента.
- `npm run typecheck:server` — проверка типов сервера. Сборки у сервера нет: Node 24 запускает `.ts` напрямую, поэтому в импортах сервера пишем расширение `.ts`, а синтаксис только стираемый (`erasableSyntaxOnly`: без `enum`, `namespace`, parameter properties).

## Документы проекта

- [ARCHITECTURE.md](ARCHITECTURE.md) — полный набор обязательных правил проекта.
- [conspects/](conspects/) — конспекты уроков, первоисточник правил. Целиком не загружаются: открывай, когда нужно понять, _почему_ правило именно такое.
- [README.md](README.md) — коротко для людей: адрес приложения, быстрый старт, npm-команды, деплой. Архитектуру, структуру папок и сценарии проверки туда не пишем (они устаревают), а ссылаемся на `ARCHITECTURE.md`.

### Новый урок

1. Конспект кладём в `conspects/` с номером: `NN-short-topic.md` (`02-stores.md`).
2. Новые правила из него переносим в `ARCHITECTURE.md` в формате пронумерованных пунктов.
3. Если правило противоречит текущему коду или другому правилу — сначала обсуждаем с пользователем, потом меняем.

## Архитектура

Перед изменениями прочитай [ARCHITECTURE.md](ARCHITECTURE.md) целиком. Применяй его правила при выборе слоя, размещении файлов и проверке изменений. Если задача затрагивает архитектурное правило или его трактовку, сверяйся с этим файлом и при ответе без правок.

## Git-процесс

- **Никогда не коммить и не пушить напрямую в `main`.** Каждый push в `main` запускает деплой на GitHub Pages.
- Каждая задача делается в отдельной ветке от свежего `main`. При начале новой задачи прочитай [start-task](.claude/skills/start-task/SKILL.md) и следуй его шагам. Когда пользователь просит оформить завершённую задачу, прочитай [finish-task](.claude/skills/finish-task/SKILL.md) и следуй его шагам.
- Имена веток: `<тип>/<kebab-case-на-английском>`, коротко, 2–5 слов.
  - `feature/` — новая функциональность
  - `fix/` — исправление бага
  - `refactor/` — переработка без изменения поведения
  - `docs/` — документация, `ARCHITECTURE.md`, конспекты
  - `chore/` — настройки, зависимости, CI
- Сообщения коммитов: коротко, на английском, в нижнем регистре, как в истории проекта (`tune debounce and empty state`).
- В `main` ветка попадает только через Pull Request со squash merge. Merge делается только после явного подтверждения пользователя.
- Проверки делают git-хуки (`simple-git-hooks`, скрипты в `scripts/hooks/`): `pre-commit` запрещает коммит в `main` и гоняет Biome по файлам коммита, `pre-push` запрещает push в `main` и запускает `npm run build` и `npm run typecheck:server`. Не обходи их через `--no-verify`. После клонирования хуки ставятся сами при `npm install`.
